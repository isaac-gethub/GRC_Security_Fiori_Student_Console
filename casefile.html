Lab B3 — The Stage With No Way Out

MSMP / BRF+ workflow technical build · Intermediate, session 9 · one of your three marked builds.

1 · The ticket

The approved design for contractor access requests specifies manager approval, then compliance sign-off, with a mandatory end date. Building the BRF+ routing rule for the compliance stage, you find the design doesn't say what happens if the named compliance approver is on leave — and without a fallback, the workflow simply stalls.

2 · Why it matters

Any contractor request submitted while the approver is out gets stuck indefinitely, with no escalation — defeating the mandatory sign-off the design was built to enforce.

3 · Diagnose before you build

Design a fallback agent-determination rule that preserves the sign-off requirement — never auto-approving — while preventing an indefinite stall. The manager-approval stage already has a fallback pattern; that is your template.

4 · Build it
  1. Confirm the backup compliance approver in writing, and check their role includes compliance sign-off authorization.
  2. Agree the timeout window with the compliance team.
  3. Build the BRF+ escalation rule in the ZZ_TRAIN_ namespace, mirroring the manager-stage pattern.
  4. Test a request left unanswered for the full window: it must escalate to the backup — never approve and never stall.
5 · Stakeholder pushback

“Won't adding a backup approver dilute the compliance sign-off — now two people can approve it instead of one accountable owner?”

Answer it yourself first — then reveal the model answer

The backup only activates after the primary has had the full window and hasn't acted — it's an escalation path, not parallel approval authority. The primary stays the accountable owner for every normal-path request; the backup exists only to prevent an indefinite stall, the same way the manager-approval stage already works.

Escalation question: the compliance team wants no timeout at all — every request waits for the primary, however long it takes. How do you respond?

Why this isn't a manual

Most SAP access training teaches you where the buttons are. This teaches you what to look for before you touch one.

Conventional trainingSet a timeout on the stage so it auto-approves. Save. Test.

It clears the stuck requests — by removing the control the stage exists to enforce.

The method

Because this is the order a real engagement forces on you — and rehearsing it lab after lab is what makes it automatic on a client system.

The thread through every lab

Every case ends by naming the pattern, not just the fix.

The test: would a failure actually show up in the evidence you're relying on? If not, you are holding the wrong evidence.

The same error — mistaking a status flag or a sign-off for proof that access is actually controlled — comes back in a different disguise lab after lab. Recognising the pattern is what lets you catch it on a system you've never seen.
